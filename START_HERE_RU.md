# Как проверить и сдать Assignment 3

Проект подготовлен для **Java 17**. В `submission.json` уже стоит `"Java"`.
В `src/Java/Algorithms.java` реализованы все шесть алгоритмов и восстановление
маршрута. Английский отчёт находится в `ANALYSIS.md`. Собственные тесты,
обоснованные ожидаемые ответы, фактические результаты и реальные измерения
Kruskal/Prim находятся в `tests/`.

## 2. Создай свою копию шаблона

Открой [исходный репозиторий задания](https://github.com/RZhaniya/daa-assignment-3-graphs)
и выбери **Use this template → Create a new repository**. Укажи свой аккаунт
как Owner и, например, имя `daa-assignment-3-graphs`. Если выбираешь Private,
предоставь преподавателю доступ по инструкции ниже.

Распакуй архив. Внутри находится папка `daa-assignment-3-graphs-java17`.
Её содержимое нужно положить в корень своей копии репозитория. В корне должны
лежать `submission.json` и `ANALYSIS.md`, рядом с папками `src`, `tests`,
`tools`, `docs`. Не создавай дополнительный уровень вложенности вокруг проекта.

### Вариант через Git

Сначала клонируй именно свой новый репозиторий. Замени `YOUR_USERNAME` на свой
GitHub-логин, а имя репозитория — на фактически выбранное:

```sh
git clone https://github.com/YOUR_USERNAME/daa-assignment-3-graphs.git
cd daa-assignment-3-graphs
```

Скопируй сюда содержимое распакованной папки с заменой совпадающих файлов.
Сохрани структуру каталогов, включая `.github` и `.gitignore`. Собственную
папку `.git` клонированного репозитория оставь на месте; в архиве её нет.
В `.github/workflows` должны быть исходный Public checks и добавленный
`student-checks.yml`.

Затем выполни проверки и загрузку:

```sh
python tools/run.py --setup
python tools/run.py --check
python tests/run_tests.py
git status
git add .
git commit -m "Implement Java graph algorithms, own tests and analysis"
git push origin main
git rev-parse HEAD
```

Если главная ветка называется иначе, используй её имя вместо `main`.
Для проверки и сборки нужны JDK 17 и Python 3.12+. На Windows можно заменить
`python` на `py -3`, а в Linux/macOS — на `python3`, если так называется
установленный Python. Команда `javac -version` должна работать: одного JRE
недостаточно.

Если хочешь заново провести измерения, отдельно запусти:

```sh
python tests/run_benchmark.py
```

Эта команда обновит файл фактических измерений. При сдаче нового измерения
обнови соответствующую таблицу и описание среды в `ANALYSIS.md`, чтобы отчёт
совпадал с `tests/benchmark_results.json`. Исходный архив уже содержит
согласованные реальные измерения; для простой проверки корректности
перезапускать бенчмарк не требуется.

### Вариант через сайт GitHub

В своей копии шаблона открой **Add file → Upload files**. Загрузи содержимое
распакованной папки с сохранением каталогов, затем сохрани изменения коммитом.
Нужны сами файлы проекта: загрузка одного ZIP-файла не даст Actions доступа
к `submission.json`, исходникам и тестам. Если браузер не показывает
`.github`, проверь её отдельно: исходный workflow уже есть в копии шаблона,
а добавленный `student-checks.yml` можно загрузить в `.github/workflows`.

Убедись, что изменённый `src/Java/Algorithms.java`, `ANALYSIS.md` и новые файлы
`tests/` действительно находятся на GitHub. Папки остальных языков — часть
исходного шаблона; выбран только Java, дописывать другие реализации не нужно.

## 3. Проверь GitHub Actions

Открой **Actions → Public checks** и дождись успешного запуска для того
коммита, который собираешься сдавать. Дополнительный workflow **Student tests**
запускает собственные тесты. Если Actions отключены в новой копии, включи их
и запусти workflow. При ошибке открой красный job и прочитай лог; зелёный
`--setup` сам по себе не означает, что прошли алгоритмы.

После исправлений появится новый коммит: использовать нужно ссылку именно
на окончательную проверенную версию.

## 4. Дай преподавателю доступ к Private-репозиторию

Путь в GitHub: **Settings → Collaborators → Add people**. Укажи точный
GitHub-аккаунт преподавателя, подтверждённый в материалах курса или у самого
преподавателя. Не определяй получателя только по имени. Доступ появится после
принятия приглашения. Ссылка на private-репозиторий сама по себе доступа
не предоставляет.

## 5. Сдай точный коммит в Moodle

Открой последний коммит в своём репозитории и скопируй его полный URL. Либо
возьми полный SHA из `git rev-parse HEAD` после push. Нужен такой формат:

```text
https://github.com/YOUR_USERNAME/daa-assignment-3-graphs/commit/FULL_40_CHARACTER_COMMIT_SHA
```

Это шаблон формата, а не готовая ссылка: подставь свой аккаунт, фактическое
имя репозитория и SHA своего коммита. У исходного репозитория преподавателя
другой владелец, поэтому его URL не является ссылкой на твою выполненную работу.

В Moodle открой Assignment 3 и вставь точную ссылку в **Online text**. При
желании добавь второй строкой URL успешного Actions run для того же коммита.
Сохрани текст, затем нажми **Submit assignment** и проверь, что работа имеет
статус отправленной на оценивание, а не черновика. Если Moodle дополнительно
просит подтвердить отправку, заверши этот шаг.

Дедлайн проверяется в самой странице задания Moodle. Срок не указан в
доступном PDF; ссылка на syllabus при подготовке возвращала отказ в доступе.
Поэтому в архиве нет выдуманной даты сдачи или утверждения, что все
дополнительные правила syllabus были проверены.

## 6. Что прочитать перед защитой

В `ANALYSIS.md` раскрыто использование ChatGPT и указано, какая помощь была
оказана. Это прямо требуется README задания. Проверь правила syllabus о
допустимом использовании AI и собственноручно изучи код перед сдачей.
Раздел о проверках описывает действительно выполненные прогоны во время
подготовки, не приписывая тебе ещё не сделанные действия.

Для защиты разберись в следующих вопросах:

- Почему `find` сжимает пути, а `union` прикрепляет меньшую компоненту к большей.
- Почему минимальное ребро разреза безопасно для Kruskal и Prim.
- Почему Prim перезапускается для каждой компоненты, включая изоляты.
- Зачем Kosaraju нужны обратный порядок завершения DFS и транспонированный граф.
- Почему цикл обнаруживается по ребру в активную вершину, а не в любую посещённую.
- Почему DAG shortest paths допускает отрицательные веса, но обязан отвергнуть
  даже цикл, недостижимый из `source`.
- Почему `parent_edge` содержит исходные ID рёбер и как по ним восстановить маршрут.
- Почему суммы используют `long`, а недостижимость обозначена `null`.
